# PRD：採購單關聯單據重組與單據明細產生器（PDF → PDF + Excel）

## 1. 背景與問題

每天會收到多張採購單的相關 PDF 單據，混在同一資料夾中。需要：

1. 依採購單號把同一採購單的單據重組並合併為一份 PDF（保留原始檔）。
2. 對每份合併後 PDF 生成一份 Excel 明細（填入張數、支數）。

## 2. 目標

### 第一階段（Phase 1）：批次重組合併 PDF

* 掃描 `.\input\` 內所有 `*.pdf`（**不包含子資料夾**）
* input 內容會包含「當天所有採購單」→ 需依採購單號分組，產生多份輸出 PDF
* 四種單別：**進貨單、進貨驗收單、採購單、請購單**（單別可由檔名判斷）
* 依「同一採購單號」將單據合併成一份 PDF，合併順序固定：
  **進貨單 > 進貨驗收單 > 採購單 > 請購單**
* **保留原始檔案**（input 不做任何修改）
* 輸出至 `.\output\`，命名規則：
  **`{採購單號}-{供商代號}-{供商簡稱}.pdf`**

### 第二階段（Phase 2）：逐檔產生 Excel 明細

* 掃描 `.\output\` 內所有 `*.pdf`（每份為 Phase 1 產出的合併結果）
* 因為合併後不再有原始檔名語意，Phase 2 **只能靠內文解析**
* 對每份 PDF 產生一份 Excel（read-only 讀取 template，另存新檔）：

  * `{張數}`：以內文計算（定義見下）
  * `{採購單號}`：從進貨單內文抽取
  * `{支數}`：從採購單頁判定並計算
* 寫入 `template.xlsx`：

  * `Sheet(工作表1).Cell(C3) = {張數}`
  * `Sheet(工作表1).Cell(B3) = {支數}`
* 另存新檔：
  **`{採購單號}-單據明細.xlsx`**

## 3. 使用者故事（User Stories）

1. 我把當天所有單據 PDF 丟進 `.\input\`，執行 Phase 1 後，能在 `.\output\` 得到多份「每張採購單一份」的合併 PDF，且命名帶有採購單號與供商資訊。
2. 我對 `.\output\` 執行 Phase 2 後，每份合併 PDF 都會得到一份對應的 `{採購單號}-單據明細.xlsx`，並且 B3/C3 已填好。
3. 若某份 PDF 沒有符合抓取條件（例如缺少關鍵字），系統應產生可讀的錯誤紀錄，但**不得用備援規則亂抓**。

## 4. 核心規則（只按你給的條件抓取，不設計備援）

> **重要原則：所有欄位抽取只依據你提供的特徵與定位邏輯；抓不到就算失敗，不做任何替代推測。**

### 4.1 單號特徵（Regex）

* 採購單號：`採購單號:\s?1[0-9]{12}`
* 請購單號：`請購單號:\s?1A[0-9]{11}`
* 驗收單號：`驗收單號:\s?1[0-9]{12}`
* 進貨單號（單據號碼）：`單據號碼:\s?1[0-9]{12}`

### 4.2 供商資訊位置（Phase 1 命名用）

* `{供商代號}`：位於 **進貨驗收單** 的頁面，特徵字串：`供商代號`
* `{供商簡稱}`：位於 **進貨驗收單** 的頁面，特徵字串：`供商簡稱`
* 抽取邏輯：僅在判定為「進貨驗收單」的頁面/內容中抓取上述欄位（抓不到 → Phase 1 視為失敗或以空值處理，依你後續想要的策略在 PRD 驗收條件定義）

### 4.3 Phase 2 欄位定義

* `{張數}`：`count(text "單據號碼")`（依你的原始定義）
* `{採購單號}`：必須從「進貨單內文」抽取
* `{支數}`：

  * 採購單頁快速判定：該頁包含 `採購日期:`
  * 支數計算：採購單內的產品支數（此處允許使用 AI agent 協助找規律與計算方式，但仍應以可控輸出為主；PRD 不要求備援規則）

## 5. 範圍與非目標（Scope / Non-goals）

### In scope

* Phase 1：批次分組 + 合併輸出 PDF（多採購單）
* Phase 2：批次解析 output PDF + 生成 Excel（多檔）
* Windows 11 25H2 環境執行
* 編碼：UTF-8 BOM（適用於腳本檔/入口檔的保存規範）

### Out of scope

* OCR（明確不需要）
* 子資料夾遞迴掃描
* 自動寄信、上傳、ERP 串接、排程通知
* 自動修復或改寫原始 PDF

## 6. 介面與使用方式（使用者視角）

* 使用者只需要：

  1. 把 PDF 丟進 `.\input\`
  2. 執行 Phase 1
  3. 檢查 `.\output\` 是否生成多份 bundle PDF
  4. 執行 Phase 2
  5. 在 `.\output\` 取得多份 `{採購單號}-單據明細.xlsx`

## 7. 驗收條件（Acceptance Criteria）

### Phase 1

* 能處理同一天多張採購單（input 混在一起）並輸出多份 PDF
* 每份輸出 PDF 的內容順序必須符合：
  `進貨單 > 進貨驗收單 > 採購單 > 請購單`
* 輸出檔名必須符合：
  `{採購單號}-{供商代號}-{供商簡稱}.pdf`
* 不允許以備援規則「猜測」供商代號/簡稱；抓不到則判定該 bundle 命名資訊缺失（由系統記錄失敗）

### Phase 2

* 對 `.\output\` 每一份 PDF 都會嘗試生成 Excel
* 成功者：`template.xlsx` 的 B3/C3 正確寫入並另存成 `{採購單號}-單據明細.xlsx`
* 失敗者：必須留下錯誤紀錄（指出缺少哪個關鍵字/欄位），但不得用備援亂抓

## 8. 風險與限制

* 若某些單據內文不含指定關鍵字（例如供商欄位名稱不同、或採購日期字樣不同），將直接造成失敗（因為不設計備援）
* `{張數}` 以文字出現次數計算，若單據格式在同頁重複出現「單據號碼」可能導致張數偏大（此為既定定義的風險，除非未來調整口徑）
* `{支數}` 的計算規律需在真實採購單樣本中固化；AI agent 需受控（避免輸出不一致）

# 最終合併需求（整合階段）

在 Phase 1 與 Phase 2 都各自完成並通過驗收後，需提供「合併版」的一鍵入口：

* 提供單一指令（或單一入口腳本）可一次完成：

  1. Phase 1：input → output bundle PDFs
  2. Phase 2：output bundle PDFs → 明細 Excel
* 仍需保留「可單獨執行 Phase 1 / Phase 2」的能力（方便重跑與除錯）
* 合併版需保證：

  * Phase 1 完成後才會進入 Phase 2
  * Phase 1 若有失敗，不得用不明備援讓 Phase 2 產生錯誤 Excel；必須以明確狀態決定是否跳過該筆
